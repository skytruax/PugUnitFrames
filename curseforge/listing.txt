Name
    Pug Unit Frames

    The addon was first called Free Unit Frames, which was taken on CurseForge. It is a homage to
    PitBull Unit Frames 4.0 and deliberately does not carry that addon's name: it is another
    team's, and CurseForge's Moderation Policies say "Your project should contain distinct content
    and assets, including in its name, avatar, summary and description." and "Names should not
    contain game name, class name versions, file versions ect....". So it is another dog: a pug,
    which is also what every player calls a pick-up group.

    Check that the name is free when you put it in. If you want search words in the name too
    (search matches the name first), this is 126 characters of the field's 128:
        Pug Unit Frames - PitBull-Style, but Lighter: Player, Target, Focus, Pet, Party & Raid Frames with Cast Bars, Auras and Threat
    "PitBull-Style" there describes; the description credits PitBull and says this is not it.

Summary
    Light unit frames written from scratch for Forever, a homage to PitBull: clean class-coloured player, target, focus, pet, party and raid frames that keep working in combat, with auras, cast bars, threat, range and dispel highlights. No libraries, no setup.

    256 characters, which is all the field takes. It asks for one clear sentence. Search matches
    the name and the summary, so between them they carry what people type: unit frames, PitBull,
    Forever, party, raid, auras, cast bars.

Logo
    curseforge/logo.png (400 x 400): a pug looking out of the bronze compass ring of FreeControl's

Description
    curseforge/description.html, pasted into the editor's source view (the "<>" button).
    It is built from description.md by: python3 tools/make_listing.py description
    Its pictures are stored on GitHub, as FreeControl's are: the moving demo (docs/demo.gif) and
    seven of the gallery pictures at a smaller size (curseforge/web/). The page loads them from
    there, so there is nothing to upload for them. The "?v=" on each link is there so that a
    changed picture is fetched afresh: raise it in description.md when the pictures change.
    Near its top it credits PitBull Unit Frames 4.0 and its authors, calls this a homage, and
    says it is not that project. Keep that paragraph whatever else changes.

Images, in this order
    your own screenshots from the game first, then curseforge/gallery/01-hero.png, 09-in-play.png,
    and 02-frames.png to 08-logo.png (1920 x 1080 each). 09-in-play is the addon's own code
    drawing a fight in the simulator; the others are illustrations. Each says on the picture what
    it is, and credits the game's spell icons and raid marks on the frames to Blizzard.
    All of them were drawn again on 2026-11-24 and 25, after 0.3.3: for the look the frames have
    since 0.3 (portraits, first name and surname on a line of their own, the party's buffs above
    each member, shields after the health) and with the settings they start with since the
    version after 0.3.3 (health as an amount, levels on the party, no mark on the target, no
    shadows). Upload all nine again, in place of whatever is there.

Files
    0.1.0 (uploaded by hand) and 0.1.1 (by the release workflow) are the addon under its first
    name, in a folder called FreeUnitFrames. From 0.2.0 it is Pug Unit Frames in a folder called
    PugUnitFrames, with the command /pug. Archive the two old files once 0.2.0 is up, or someone
    will install an addon whose name is not the page's.

Releasing a version: by pushing a tag
    1. The project id is in PugUnitFrames/PugUnitFrames.toc ("## X-Curse-Project-ID: 1826652").
    2. This repository has the upload token as a secret named CF_API_TOKEN (since 2026-11-23).
       It is the author API token FreeControl's repository uses (authors.curseforge.com > API
       tokens), and it is the account's, not one project's. The Core API key you can apply for
       separately is a different thing and is not needed for any of this.
    3. Push a version tag (git tag -a v0.2.0 -m "Pug Unit Frames 0.2.0"; git push origin v0.2.0).
       The release workflow builds the zip, makes a GitHub release and sends the file to
       CurseForge with CHANGELOG.md as its changelog.
    Never run an old tag's workflow again: it would send that version to CurseForge a second time.
